# Research-First Content Plan Optimizer
 
## Purpose
 
Use this skill whenever generating an SEO, AEO, GEO, AI-search, topical-authority,
editorial, or 30-day content plan.
 
This skill controls the research and validation process.
 
The user's content-plan prompt controls the requested output structure.
 
Do not unnecessarily rewrite, expand, or replace the user's original prompt.
 
---
 
# 1. OPTIONAL DATA UPLOAD — ALWAYS ASK FIRST
 
Before researching or generating the content plan, ask the user whether they
want to upload additional SEO data.
 
Ask:
 
"Before I begin, would you like to upload a metadata file, a keyword data file,
both, or would you like to skip this step?"
 
The upload is optional.
 
The user must be able to respond with:
 
- Metadata file
- Keyword file
- Both
- Skip
If the user chooses Skip, continue immediately.
 
Do not ask for the files again after the user has skipped.
 
Do not block content-plan generation because optional files were not provided.
 
---
 
# 2. USE UPLOADED DATA WHEN AVAILABLE
 
If metadata data is supplied, use relevant available fields to understand:
 
- existing URLs
- existing titles and metadata
- current content coverage
- duplicate or overlapping pages
- content gaps
- refresh opportunities
- consolidation opportunities
- possible cannibalization
- internal-link destinations
If keyword data is supplied, use relevant available fields to understand:
 
- current queries
- rankings
- impressions
- clicks
- CTR
- search volume
- trends
- ranking URLs
- search intent
- keyword opportunities
- declining opportunities
- striking-distance keywords
- high-impression/low-CTR opportunities
- potential cannibalization
Only use fields that actually exist.
 
Never invent missing values.
 
Check dates/reporting periods before treating uploaded data as current.
 
Uploaded data is a first-party signal, not automatic proof that a topic is
currently trending.
 
---
 
# 3. RESEARCH BEFORE TOPIC SELECTION
 
Never select the final article topics first and research them afterward.
 
Before proposing topics, research the current market and search landscape.
 
Where live research tools are available, use them.
 
Research should cover relevant signals such as:
 
- current search behavior
- recent search-result patterns
- current audience questions
- emerging queries
- recent industry developments
- product/platform changes
- official announcements
- recently updated documentation
- current competitor content
- emerging technologies
- new workflows or standards
- regulatory changes where relevant
- current terminology
- emerging terminology
- declining or obsolete terminology
Prioritize developments from:
 
1. The last 30–90 days
2. The last 6 months
3. The last 12 months
Older information may still be used when it remains relevant and authoritative.
 
Historical popularity alone is not sufficient reason to recommend an article.
 
If live/current research is unavailable, say so clearly.
 
Never pretend that training knowledge is live research.
 
---
 
# 4. VALIDATE FRESHNESS
 
Every proposed topic must have a defensible reason to be included now.
 
Use multiple signals where possible, including:
 
- recent SERP activity
- search trends
- related searches
- search suggestions
- audience questions
- official documentation
- recent announcements
- industry publications
- recent research
- competitor activity
- professional/community discussion
- first-party keyword data
- first-party metadata/content data
Do not call something:
 
- trending
- emerging
- rising
- growing
- newly relevant
- popular
unless current evidence supports it.
 
High search volume alone does not mean a topic is trending.
 
A single competitor article alone does not prove a market-wide trend.
 
---
 
# 5. USE CURRENT TERMINOLOGY
 
Do not automatically reuse terminology because it was historically common.
 
For important topics, determine whether the market currently uses:
 
- established terminology
- current terminology
- emerging terminology
- alternative terminology
- declining terminology
- superseded terminology
Prefer language currently used by the target audience.
 
If an older term still has search demand while a newer term is gaining adoption,
use both strategically where appropriate.
 
For example:
 
Older keyword → useful for established search demand
 
Newer terminology → useful in the article title, secondary keywords, headings,
FAQs, entities, or conversational queries where justified
 
Do not invent terminology changes.
 
---
 
# 6. REJECT OUTDATED OR WEAK TOPICS
 
Before finalizing the content plan, challenge every proposed topic.
 
Reject, refresh, consolidate, replace, or reframe it when:
 
- the topic is outdated
- the underlying technology has changed
- official guidance has changed
- terminology has been superseded
- audience interest has materially declined
- a newer question is more important
- the website already sufficiently covers the same intent
- creating another article would create unnecessary cannibalization
- an existing page should be refreshed instead
- the topic is heavily saturated without a credible differentiated angle
- current evidence does not support its relevance
Evergreen topics are allowed when they remain genuinely relevant today.
 
Do not reject an evergreen topic merely because it is old.
 
The question is whether it remains useful and strategically valuable now.
 
---
 
# 7. BALANCE THE CONTENT PLAN
 
Do not force all 30 articles to be trend-driven.
 
Maintain a useful balance between:
 
### Emerging
New topics, terminology, technology, behavior, or audience problems.
 
### Trending
Established topics currently receiving increased attention.
 
### Current Evergreen
Long-term topics that remain demonstrably relevant.
 
### Refresh Opportunities
Existing subjects whose current treatment has become outdated.
 
Prioritize audience relevance, business relevance, and topical authority over
novelty alone.
 
---
 
# 8. "WHY NOW?" TEST
 
Before accepting any proposed article, internally answer:
 
"Why should this website publish this article now?"
 
A valid answer should be based on one or more of:
 
- current search demand
- emerging search behavior
- recent market development
- recent product/platform change
- new terminology
- a competitor/content gap
- first-party keyword opportunity
- existing content decay
- current audience problem
- commercial opportunity
- topical-authority gap
If there is no convincing answer, replace the topic.
 
---
 
# 9. SOURCE AND DATE DISCIPLINE
 
When freshness affects a recommendation:
 
- prefer primary and authoritative sources
- check publication/update dates
- use specific calendar dates where useful
- distinguish factual evidence from strategic inference
Prefer approximately:
 
1. Official documentation
2. Official announcements/changelogs
3. Search-engine/platform documentation
4. Government, academic, regulatory, or standards sources
5. Original research
6. Trusted industry publications
7. Expert analysis
8. Competitor content
9. Professional/community discussions for discovery signals
Do not fabricate:
 
- trends
- search volume
- rankings
- statistics
- source dates
- citations
- announcements
---
 
# 10. EXISTING CONTENT BEFORE NEW CONTENT
 
Before recommending a new URL, inspect the website, sitemap, and uploaded
metadata when available.
 
Determine whether the appropriate action is:
 
- Create
- Refresh
- Expand
- Consolidate
- Reposition
Prefer improving an existing page when it already satisfies substantially the
same search intent.
 
Avoid unnecessary keyword cannibalization and semantic duplication.
 
---
 
# 11. INTERNAL LINKS
 
When recommending internal links, use verified URLs only.
 
Relevance takes priority over keyword similarity in the URL.
 
Evaluate:
 
1. Topic relevance
2. Search-intent match
3. Reader usefulness
4. Contextual relationship
5. Topical specificity
6. Site hierarchy
7. Commercial relevance when appropriate
Never invent an internal URL.
 
Never choose a page solely because its URL contains the keyword.
 
If no suitable verified destination exists, do not force a link.
 
Use:
 
"No suitable internal link found"
 
when appropriate.
 
---
 
# 12. FINAL QUALITY CHECK
 
Before returning the content plan, verify:
 
- current research occurred before topic selection
- each topic has a valid reason to exist now
- terminology is current
- trend claims are supported
- uploaded data was used when supplied
- no missing metrics were invented
- existing content was checked
- cannibalization was considered
- refresh opportunities were considered before creating new pages
- internal URLs are verified
- recommendations reflect current audience and business needs
Replace or reframe recommendations that fail these checks.
 
---
 
# 13. DOWNLOAD / EXPORT
 
After generating and displaying the complete content plan, ask:
 
"Would you like to download this content plan as a file?"
 
If file-generation capabilities are available, offer only genuinely supported
formats.
 
Preferred formats where available:
 
- XLSX for operational content planning and filtering
- DOCX for the complete strategy
- Markdown for portable AI/content workflows
- CSV for the main content-plan dataset
- PDF for a fixed reference version
If the user selects a format and file creation is supported:
 
1. Create the actual file.
2. Preserve the generated content plan.
3. Provide the downloadable file.
4. Do not call a code block a download.
5. Do not materially change the strategy during export.
If file generation is unavailable, state that clearly.
 
The content plan must still be shown in the normal response.
